# Procédure d’incident de sécurité

1. Qualifier la gravité, ouvrir une chronologie et nommer un responsable.
2. Contenir sans détruire les preuves : révoquer sessions/clefs concernées, isoler le composant, préserver audit, logs et snapshot.
3. Identifier périmètre, établissements, personnes et transactions touchés ; le journal d’audit est en lecture seule.
4. Éradiquer, corriger, restaurer depuis une source vérifiée et rapprocher les données financières.
5. Informer direction, établissements et autorités/personnes selon les obligations applicables ; aucun détail personnel dans les canaux non sécurisés.
6. Clore par une analyse causale, actions datées et exercice de non-régression.

Alertes critiques immédiates : API indisponible, tentative d’altération financière, fuite suspectée, écarts de solde ou webhook invalide massif. Les coordonnées d’astreinte sont tenues hors dépôt dans le gestionnaire d’incidents.
